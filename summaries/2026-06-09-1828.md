## ⚠️ Important: a corrupt checkpoint commit was created and removed

At run start, `git status` showed all 8 recently-touched files as
modified. Per protocol I committed them as `checkpoint: pre-run working
tree` (33d1d47) via `git add -A` — but the sandbox mount serves file
reads NUL-padded to a stale size and with CRLF, and because the NULs
made git treat the files as binary, the corruption went into the blobs
verbatim (committed gameLogic.js failed `node --check`).

Investigation showed every "modified" file was **byte-identical to
HEAD after stripping trailing NULs and normalizing CRLF→LF** — i.e.
the working tree had NO real changes; the modifications were pure mount
artifacts. The checkpoint was 100% noise, so I removed it: develop was
pointed back to 22a3d61 by writing `.git/refs/heads/develop` directly
(stale `.lock` files — index.lock, HEAD.lock, develop.lock — exist and
cannot be unlinked from the sandbox; lock-free plumbing was required)
and the index was rebuilt via `GIT_INDEX_FILE` + `cp`. 33d1d47 is now
dangling and was never pushed. **Lesson recorded for future runs: never
trust `git add` from the sandbox; build blobs from NUL-stripped,
LF-normalized content and verify with `node --check` / byte-compare
before committing.**

If the stale `.lock` files cause Mark trouble on the host, deleting
`.git/index.lock`, `.git/HEAD.lock`, and `.git/refs/heads/develop.lock`
from Windows is safe (no git process is running).
