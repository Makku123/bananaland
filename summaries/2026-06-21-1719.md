# Session 2026-06-21 1719 — Rune cards show grow (green) | walk (purple) split

User: "for runes, show the number that the rune will grow on the left side, and how much they will
walk on the right side and have a line dividing the two numbers on the card. make the grow side green
and the walk side purple. If you have a rune, and there is no grow tile revealed that matches it. Keep
it looking the same way as it does now with just one number on the card and purple."

## Mechanic this surfaces (was NOT in my memory — added by user/linter recently)
`_growMatchMove(player, value)` in gameLogic.js: when a played rune value (1–6) matches a **revealed**
grow's label, that grow fires AND the player hops **7 − value** tiles instead of `value`. The
firing/reveal gate is `_isGenuinelyRevealed` (a grow revealed by ANY player — grow reveals broadcast
to everyone). So a rune's two numbers are:
- **grow** = the rune value `v` (the grow # it triggers) — GREEN, left.
- **walk** = `7 − v` (the hop when that grow fires) — PURPLE, right.
- No matching revealed grow → it just walks `v`: single purple number (unchanged).

## Change (frontend only)
- `game-screen.js` `makeChip`: precompute `revealedGrowLabels` from `gs.boardLayout` (a grow appears
  there only when revealed to the viewer — which equals the firing condition, since grow reveals are
  global). Per chip: `willGrow = revealedGrowLabels.has(v)`, `walk = willGrow ? 7-v : v`. If willGrow,
  add class `roll-chip-split` and render `<span class="roll-chip-grow">v</span><span
  class="roll-chip-walk">7-v</span>`; else the existing single `.roll-chip-val`. aria-label updated
  ("grows V and walks W").
- `styles.css`: new `.roll-chip-split` (align-items:stretch) + `.roll-chip-grow` (green gradient,
  rounded left corners, white numeral) + `.roll-chip-walk` (transparent so the card's purple shows,
  light numeral, **`border-left:2px` = the dividing line**, faint purple glow). Numbers at z-index 2
  (above the holo shine). Single-number chips are untouched.
