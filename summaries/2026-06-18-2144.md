# Run summary — 2026-06-18 21:44 PT

Added a new **Quick Mode** (a single lobby toggle that replaces the pineapple-bomb
toggle), changing how the Super Banana behaves so games end faster.

## Quick Mode spec (implemented)
- **One toggle replaces the bomb toggle.** `quickMode` ON → **bombs removed**;
  OFF → bombs are in the game. `bombMode` always tracks `!quickMode`. The
  separate pineapple-bomb toggle is gone (create form + lobby).
- **The Super Banana never hides or relocates** in quick mode — it stays on its
  tile all game (no `_relocateSuperBananaHidden`).
- **Can't afford it (cross OR land):** you get an adjustable **banana bonus**
  (`quickBananaBonus`, default **20🍌**, lobby-adjustable, minted + ledger-tracked).
  Crossing pays out only if the tile is **revealed**; **landing** pays even if it
  was hidden (landing reveals it). Repeatable; the SB stays put.
- **Can afford it:** you **buy it and win**.
  - **FFA (classic):** win by **crossing a revealed SB OR landing** on it.
  - **2v2 / 3v3:** you must **LAND** to buy — crossing while affordable does
    nothing (and gives no bonus, since you could afford it).
- A **hidden** SB merely crossed does **nothing**. A **ghost** never buys/wins —
  it just collects the bonus.

## Note (not a bug — base-game interaction)
Because the Super Banana stays put in quick mode, a can't-afford player can be
**parked on it**. If an opponent then lands on that same tile, the normal
shared-tile **Monkey Poker** duel fires (the SB branch in `_processLanding` is
reached only after the poker check), so that lander duels instead of getting the
bonus that turn. This is existing two-monkeys-on-one-tile behavior and only
applies in the rare simultaneous-occupancy case (the parked player has moved on by
their own next turn). Left as-is; flag if you'd want the SB bonus to take
precedence over poker on the Super Banana tile.
