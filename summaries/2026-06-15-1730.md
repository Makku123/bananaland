# Run summary — 2026-06-15 17:30 PT

Three user-requested gameplay fixes: (1) pineapple bombs were invisible when
placed — make them visible with a timer; (2) allow bombs on corner tiles,
where they blast forward to the next corner; (3) vine swing must not allow
swinging to the tile you're already on. Asked two clarifying questions on #1
first — user chose: keep the arming delay but show the placer their bomb
during arming, and keep bombs placer-only (secret from opponents).

## 1. Bomb visibility during arming (placer-only)

Bombs were deliberately `pending` (invisible) until they armed at the end of
the placer's next turn; the board render did `if (bomb.pending) continue`.
Now `board.js` renders pending bombs too, in an "arming" state — the existing
(but previously dead) `.bomb-arming` CSS (dimmed pineapple, slow pulse) with
an ⏳ hourglass badge and a "goes live in N turns" tooltip — then switches to
the numeric 3→0 countdown once armed. `gameLogic.js` serialization now
includes `armCountdown` on the placer's bombs so the tooltip can show
turns-until-live. Visibility is unchanged: the server still only sends a
player their OWN bombs, so opponents never see them.

## 2. Corner-tile bombs with forward-only blast

Dropped the corner-placement restriction in `placeBomb` (backend) and both
frontend `bomb-target` checks in `board.js` (the `i % 12 !== 0` guards).
`_bombBlastTiles` now branches: a non-corner bomb keeps the two-way
corner-to-corner side blast; a bomb ON a corner blasts **forward (clockwise)
only**, from its corner up to and including the next corner. For corner 0
that's the 13 tiles 0..12.

## 3. Vine swing can't target the current tile

Added a `pos === player.position` reject in backend `_validateTeleportTarget`
and the mirrored frontend `_isAbilityTileSelectable` (game-items.js), so your
own current tile is no longer offered or accepted as a swing target.
