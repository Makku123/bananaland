- Swaps `Math.random` for a seeded PRNG (mulberry32), per the 06-10 flaky-test
  rule: randomized tests must pin their randomness. Runs are fully
  deterministic — 15 consecutive identical green runs today.
- Plays 6 configs to completion (or a 4,000-step budget) through the public
  API only: 2p/3p/4p classic, 4p 2v2, a 300🍌 "poor" game (sealed-bid/broke
  paths), and a 2v2 game with real start-tile picks. The driver resolves
  whatever the game is waiting on — poker (random call/raise/fold), property
  and item auctions through every phase (pitch/respond/silent/sealed, incl.
  rewinding the 2v2 teammate 5s gate), Super Banana hideout picks, start
  picks — and otherwise buys/places bombs, trades, arms items, vine-swings,
  uses Roll One/dice items, rolls, and ends turns.
- Invariants checked throughout: integer money, legal board positions,
  property↔owner list consistency (both directions), `getState(viewer)`
  serializes for every player, and **no deadlock** — if no API call succeeds
  for 200 consecutive driver steps the test fails with a state snapshot.
  Also requires ≥2 of the 6 games to reach an actual win.

Driver subtleties discovered while building it (now encoded in the test):
start-tile picks are current-player-only and count as the turn's roll, and a
pick that lands on an unowned farm opens an auction that blocks the remaining
picks — the driver had to learn the real game's ordering, which is exactly
the kind of sequencing the isolated sections never exercise.
