# Session 2026-06-19 2100 — Super Banana cross behavior (+50) finalized to the full matrix

Request: make the Super Banana behave exactly as a 4-quadrant matrix.

| | Land | Cross |
|---|---|---|
| **Can't afford** | g-roll auction | **+50 bananas** |
| **Can afford** | win | g-roll auction |

Only one quadrant differed from existing behavior: **can't-afford + cross**, which previously
did nothing. The user clarified the +50 should apply **only when the SB is already REVEALED and
crossed**; crossing it while still fog-hidden does nothing (preserving "crossing never reveals
the SB").

## Change (backend only) — `_resolveSuperBananaCross` in gameLogic.js
Restructured to find the crossed `sbPos` first, then branch:
- **Can afford** → guaranteed-roll card auction (`_startCardAuctionPick`). This is INTERACTIVE, so
  it keeps the bail: if the landing already opened a farm auction / poker / win, it yields (two
  auctions can't stack). Unchanged behavior.
- **Can't afford + `player.revealedTiles.has(sbPos)`** → `player.money += 50` + `bananaLedger.minted
  += 50` + log. This is PASSIVE — it fires regardless of what the landing tile did (like collecting
  a banana pile on the crossed path), so **every** walk-over of a revealed SB pays out. Removed the
  old top-level `if (this.auction||this.poker||this.superBananaWin) return;` guard (which would have
  skipped the +50 whenever you also landed on a farm — ~half the time — feeling like a bug).
- Hidden SB crossed → nothing; crossing never reveals; ghosts/bankrupt excluded.

Why the +50 must mint: it creates bananas, so the conservation ledger gets `minted += 50` paired
with the `money += 50`.

## Residual note (by design, not a bug)
A **rich** crosser who also lands on a farm/player gets that landing's auction/duel, not the g-roll
(can't stack two auctions). The **passive +50** has no such limit — it always pays on a revealed-SB
cross. This asymmetry (passive pays always; interactive yields) is intentional.
