# Run summary — 2026-06-16 12:19 PT

a multi-agent adversarial review that caught and fixed a privacy leak.

## New 2v2 model

- **Pitch.** A1 names price **P** (1🍌 min, richest-other cap). Eligible
  responders = non-lander players with money ≥ P and > 0 (not bankrupt/ghost).
- **Respond.** Every eligible player **accepts/rejects simultaneously** (no 5s
  teammate wait). Resolves when all answer or the timer expires (stragglers =
  reject).
- **Team twist.** Only **one opponent** can accept — whoever's **first**; later
  opponent accepts are recorded but never counted.
- **Resolve.** 0 accepters → lander keeps at P (pays P) · 1 → that player buys at
  P · **opponent + teammate** → silent top-up bid (highest total wins at P+topup;
  **tie → lander** at P).
- **Buy Now** (kept teammate's say): pitches highest-opponent+1 → only the
  teammate can afford it → accept (teammate buys) / reject (lander buys); teammate
  can't afford → lander buys instantly.
- **Broke lander** folds in as a pitch of **0**: same rules; a tie or no takers
  leaves the farm with A1 **free**; both A1+A2 broke → first opponent to accept
  gets it free.
- **Privacy** (new rule): a viewer sees only their **own** and their
  **teammate's** accept/reject — never the other team's; silent-bid top-ups stay
  own-only.

## Review → fix

Ran a 4-dimension adversarial **Workflow** (12 agents) with independent skeptic
verification of each finding. It surfaced **one real (major) bug**, refuted none:

- **Privacy leak — `firstAcceptorId`.** getState serialized `firstAcceptorId`
  unconditionally, so during the live respond window the lander's team could read
  which opponent had already accepted (the per-bid `accepted` was correctly gated,
  but this leaked the same fact). **Fixed** by not serializing `firstAcceptorId`
  at all (it's server-internal; the frontend never reads it) + regression test
  18b. Two minors also fixed: removed the now-dead broke-lander silent-tie branch
  in `_resolveSilentBid`, and `_rebindPlayerId` now remaps
  `lastResolvedAuction.winnerId`/`participantIds` for a clean post-resolve
  reconnect.
