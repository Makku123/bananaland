## Fix 1 (backend): a squatting ghost no longer blocks the tile

standing on a tile cancelled the tile itself:

- Land on the **Super Banana** with enough bananas while a ghost squats it →

still resolves (auction, SB buy/hide). Implemented by removing the early

**Mark's ruling 2 (kept as-is, now recorded):** a poker duel **replaces** the

## Fix 2 (frontend): pile boxes no longer blink/re-bounce on turn change

Mark's report mid-run. Two compounding causes in `board.js`:

1. **Detach/re-append restarted animations.** Every full `renderBoard`
   detached the `.banana-pile` chips and re-appended them after
   `board.innerHTML = ""`. Re-inserting a node restarts its CSS animations,
   and turn-end fires several full renders back-to-back — so the infinite
   glow blinked and any in-flight bounce replayed on every pass. The chips
   now stay attached; the teardown removes every other child instead
   (chips are absolutely positioned with their own z-index, so DOM order
   doesn't matter).
2. **Spurious "grew" re-flags replayed the bounce.** The grow-unfreeze render
   recomputes growth from `gs.diceMatchGrownAmounts`, which the server only
   clears on the NEXT roll — late renders could re-flag tiles that already
   bounced (e.g. land-on-grow after a rolled grow) and the replay logic
   force-restarted the animation. Chips now track the displayed amount
   (`data-shown` / `data-prevShown`) and the bounce + "+N" floater fire only
   when the on-screen number actually increases — exactly Mark's spec:
   "bounce once, and only when the banana count is increased."

Cache bust: index.html → `board.js?v=8`.

## Follow-up 3: pile boxes disappearing then reappearing (Mark's report)

Root cause in **game-socket.js**: the pile snapshot that walks freeze to
(`_prevBananaPileState`) was only rebuilt when `!window._tokenWalking`. If a
roll update arrived while the previous walk was still animating — throttled
background tab (Mark tests with several browser windows), fast consecutive
turns, or a long landing-grow pulse — the new walk froze the board to a
snapshot from BEFORE the previous turn. Any pile created/grown since then
computed 0 for the whole walk: its chip was dropped, then reappeared at
unfreeze. Reproduced headlessly before fixing: with the old guard and
overlapped walks, the grown pile's chip detaches mid-next-turn and comes
back at unfreeze — exactly the report.

Fixes:

1. **game-socket.js** — the pile snapshot is now taken unconditionally on
   every update (each rebuild is a fresh object, so an in-flight walk's
   frozen reference is untouched). Positions/money snapshots keep the guard
   (they feed different freezes).
2. **board.js** — defensive: chip reconciliation is skipped when gs has no
   properties (an empty reconcile would silently drop every chip for a
   frame), in both renderBoard and walkStepUpdate.

New **frontend/test_pile_persist.js** (second frontend test, same jsdom
approach): emulates the cross-module choreography (socket snapshot +
freeze/walk/unfreeze flags) across two consecutive turns. 11/11: happy path
clean; NEGATIVE check pins that the legacy guard reproduces the vanish;
production semantics never drop a chip across overlapped turns; sync-check
asserts the real game-socket.js snapshot sits outside the walking guard.
Bounce harness re-run on the changed board.js: 32/32. no-undef lint on both
changed files: clean. Cache busts: board.js v9, game-socket.js v3.
