# Session 2026-06-19 2004 — Guaranteed roll shown as a CARD + revealed-rolls UI refresh

Two frontend requests:
1. When a guaranteed roll is played, show a CARD bearing its number instead of a die.
2. Improve the UI where players see each other's REVEALED guaranteed rolls.

Started with a parallel **mapping workflow** (3 Explore agents) over the dice-render pipeline,
the guaranteed-roll play flow, and the revealed-rolls display — the dice/walk choreography is a
documented fragile area, so I mapped it exhaustively before touching it.

## Feature 1 — card instead of die
Key fact from the map: a played guaranteed roll arrives as `gs.dice.length === 1` (value
`gs.dice[0]` = 1–6, or 7–12 for a negative-roll card). A CANCELLED card becomes a real 2d6
(length 2) → stays dice. So no backend change: the card shows `gs.dice[0]`, the same number the
die showed.
- `index.html`: added `#roll-card-scene` (`.roll-play-card` with number/pip/label) inside `.dice`.
- `game-screen.js` (in `showGame`): `isCardPlay = gs.dice.length===1`. A scene-visibility block
  (runs every render → reconnect/walk-safe) toggles card-scene vs die-scenes and stamps the number.
  The spin/settle block branches: card play runs a `.dealing`→`.landed` CSS animation; normal roll
  keeps the original `setDieFace`/`--die-final` path. The walk / `_walkGen` / freeze choreography is
  UNCHANGED and shared — the card path only swaps the visual.
- `styles.css`: `.roll-card-scene`/`.roll-play-card*` + `@keyframes rollCardDeal/rollCardLand`.

## Feature 2 — revealed-rolls profile display
`_rollCardPanelHTML(p)` reworked from plain gold text (`🎲 2 5 5  🂠 6`) to a row of mini playing
cards: a face-up gold `.mini-roll-card-revealed` per revealed value (sorted) + one face-down
`.mini-roll-card-back` stamped with the concealed count. Speaks the same card language as Feature 1.
Old `.pstat-cards-revealed/.pstat-card-num/.pstat-cards-hidden` CSS replaced with `.mini-roll-card*`.

## Verify
- **Drove a real 2-player game in the browser preview** (page socket = P1, a second `io()` = BOT):
  - P1 played a concealed guaranteed roll → `gs.dice=[3]`, card scene shown with "3", `die-scene1`
    hidden. (Also confirmed the 6 concealed + 3 revealed hand, and "Cancel Guaranteed Roll (2 left)".)
  - BOT then rolled a normal 2d6 → `gs.dice=[2,1]`, card hidden, both die-scenes shown.
  - Screenshots captured both states; MONKEYS panel shows the new mini-cards; **no console errors**.
- `node --check` clean; `test_pile_bounce.js` 43/43, `test_pile_persist.js` 20/20 (choreography intact).
- An adversarial review workflow (2 agents) ran over the diff for edge cases (negative-roll 7–12,
  reconnect/persist, overlap vs `_walkGen`, reset `[0,0]`, coin-scene, die-scene1 restore, mini-card
  row overflow, dead CSS) — findings addressed [see follow-up].

## Notes / gotchas
- gs.dice persists between turns, so the dice area shows the last result (die or card) until the
  next roll — the scene-visibility branch runs every render so this stays correct (incl. reconnect).
- Negative-roll card shows the effective value (7–12), consistent with the old die-numeral and the
  player's own chips in negative mode.
- The coin-scene (team coin flip) is untouched; card plays never coincide with it.
