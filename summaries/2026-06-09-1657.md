# Session summary — 2026-06-09 16:57 PT (scheduled run)

## Task

Rules-compliance fix: rules.md (Leavers) says "If **every** remaining
player is a ghost except for one, that one live player just wins" — but
nothing implemented it. The only last-standing checks counted ghosts as
alive, so a lone live player among ghosts had to keep playing against
auto-rolling spirits forever.

## What changed (backend/gameLogic.js)

- New `_checkLastLiveWin` / `_lastLiveWinPending` / `_resolveLastLiveWin`
  / `_cancelLastLiveWin`: when exactly one non-bankrupt player is live
  and at least one ghost remains, the live player wins.
- **Judgment call — 10s grace window.** The rule as written collides
  with rules.md's own reconnect promise ("refresh … resume as a normal
  player"): the server ghosts a player the instant the socket drops, so
  a literal "just wins" would hand a 1v1 game to the opponent on every
  page refresh, before the refresher could ever reconnect. Instead the
  win goes on a 10-second clock (logged to all players); any ghost
  reconnecting cancels it, and ghosts keep auto-playing during the
  window. If you want it instant (or a different delay), say the word.
- Trigger points: `makeGhost` (someone leaves), `_checkBombWin` (a bomb
  leaves 1 live + ghosts, both classic and 2v2 branches), and the
  `removePlayer` mid-game path. `reconnectByClientId` cancels the
  pending win; `_clearDeferredTimers` clears the handle on reset.
- 2v2: the win is logged as the live player's team winning; the
  game-over screen is driven by the existing `bombWinner` field either
  way, so the frontend needed no changes.

## Tests (backend/test_game.js)
