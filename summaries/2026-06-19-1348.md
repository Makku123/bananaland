# Session 2026-06-19 1348 — Negative-roll toggle for guaranteed rolls

Request: add a per-player NEGATIVE toggle to guaranteed dice rolls. When on, playing a card of value N moves `13 - N` instead of N (a 1 → 12, a 6 → 7; range 7..12). Adds a strategy layer.

## Backend (gameLogic.js + server.js)
- New per-player `negativeRolls` bool: init false in `addPlayer`; reset in `_resetToLobby` + `completeReveal`; getState ships it **owner-only** (`negativeRolls: isViewer ? !!p.negativeRolls : undefined`, after the `{...p}` spread which would otherwise leak it).
- `setNegativeRolls(socketId, on)` (state playing, not bankrupt/ghost). server.js: `set_negative_rolls {on}` handler.
- `useRollCard` NORMAL-play branch: `const move = cur.negativeRolls ? 13 - N : N;` then `this.dice=[move]`, `_processRolledGrow(cur, move)`, `position += move`, walk timing uses `move`. The card is still consumed by its FACE value (splice by index). The cancel-HIT branch (card wasted → 2d6) is unchanged (negative N/A). The effective value drives die/grow/move/walk, so a negative move that lands on/crosses the Super Banana resolves correctly (position-based). Arming + negative composes: the armed selection is by face value; `useRollCard` reads `cur.negativeRolls` at play time.

## Frontend (game-items.js, game-screen.js, index.html, styles.css)
- `setNegativeRolls(on)` / `toggleNegativeRolls()` emit the event.
- Panel render: `const negative = !!(me && me.negativeRolls)`. A toggle button `#btn-negative-rolls` (in index.html, inside the panel) reflects it (label "Negative roll: ON (13 - N)" / "OFF", `.on` class, aria-pressed); the wrapper gets `.negative-mode` (amber felt accent). Chips DISPLAY `13 - N` when on (grouped still by FACE value; click still plays `group.firstIndex` of the face value — the server applies 13-N); groups reversed so shown numbers ascend 7..12; titles explain "card 1 → 13 - 1". Arming highlight still matches by face value.
- DIE display: the 3D cube only has faces 1..6, so `setDieFace` now shows the cube for 1..6 (and resets visibility + hides the numeral) and a flat numeral overlay `.die-numeral` (in die-scene1) for 7..12 (hiding the cube). The `--die-final` lines guard `DIE_TRANSFORMS[v]` with a fallback for `undefined` (v>6).
