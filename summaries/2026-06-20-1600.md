## 1. Rune Duel is now a lobby toggle (OFF by default)
- Backend: `this.runeDuel` (constructor defaults **false**). BOTH the player-vs-player
  duel trigger AND the ghost rune-swipe in `_processLanding` are gated on `this.runeDuel`
  — toggle off → landing on a lone opponent or a ghost does nothing special (per the
  user: "toggle gates everything"). `updateSettings` handles `runeDuel`; `getState` ships
  it; `server.js` create_game stamps `game.runeDuel = data.runeDuel === true`.
- `createStartedGame` (test helper) defaults `runeDuel:true` so the existing duel/ghost
  tests pass unchanged; new **103t** (production default OFF + updateSettings toggles),
  **103u** (off gates the player duel), **103u2** (off gates the ghost swipe).
- Frontend: `#create-rune-duel` toggle card (create page) + `#lobby-rune-duel` toggle

  `game-lobby.js` shows "⚔️ Rune Duels ON" + syncs the lobby checkbox from `gs.runeDuel`.

## 2. Yellow "Path Preview" highlight (standalone, toggle + 1–12)
- New control `#path-preview`: an on/off switch (`#path-preview-on`) + a 1–12 range
  (`#path-preview-range`) that highlights the viewer's next N tiles **YELLOW**
  (`.step-ahead-path`). Default off.
- The **Banana Gadget** now also highlights — a **DIFFERENT colour** so they LAYER (per
  the user): **GREEN** (`.banana-reach`) on the tiles within its 1–12 range where the
  viewer owns a collectible pile. A tile in both shows green outline + yellow fill.
- Both computed in `board.js renderBoard` (owner-only, **fog-safe** — banana-reach skips
  unrevealed tiles and only marks your own piles; the yellow path only glows the fog
  cover, no content leak), from `window._stepHiOn`/`_stepHiN`/`_bananaGadgetN`. JS:
  `togglePathPreview`/`setPathPreview`/`updatePathPreview`/`_renderBoardNow` in
  game-screen.js (per-frame `updatePathPreview()` in showGame, like the gadget).

## Adversarial review
6-agent review (4 dimensions → verify → synthesis): **GO — all four changes safe.**

destination (`.armed-path-dest`, cyan) AND inside the path-preview window
(`.step-ahead-path`, yellow) had the yellow rule win on source order, demoting the
armed destination's cyan glow/pulse/z-index. **Fixed** with a 3-class selector
`.space.step-ahead-path.armed-path-dest, .space.banana-reach.armed-path-dest`

destination wins both overlaps.
