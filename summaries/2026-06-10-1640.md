## Pile-box blink / re-bounce — root causes and fixes

Diagnosed live: ran a real 2-player game (preview server + a socket.io bot
driving the second seat with aggressive `turn_anims_complete`) with the DOM
instrumented for chip detaches and bounce-class adds. Caught the blink twice
and probed the flag state at the moment of a 9-chip mass removal.

**Cause A — stale per-turn timers.** Every walk schedules timers (dice spin
ticker, walk interval, 160ms landing cleanup, 250ms pulse start, 600ms
grow-unfreeze, 500ms finishLanding, pulse sweep steps). None checked whether
their turn was still current. With auto-roll (or a background tab flushing
throttled timers) the next roll arrives while they're pending, and a stale
`_growUnfreeze` nulled the NEW walk's `_frozenBananaPiles` / visited-tile
tracking mid-walk. Fix: `window._walkGen` generation stamp in the dice
handler (`game-screen.js`); every deferred callback no-ops when superseded.
`_runGrowPulse` (`game-lobby.js`) carries the same stamp; a stale pulse
still releases `_growPulseActive` so the end-turn ticker can't wedge.

**Cause B — next-roll gate gap (the live-caught one).** Grow reveals render
`frozenVal + grownAmount` gated by `gs.diceMatchTiles` /
`diceMatchGrownAmounts`, which the server NULLS on the next `rollDice`. A
render in the gap between that roll's update arriving and the dice handler
installing the fresh freeze fails the gate and drops every revealed pile to
`frozenVal` (often 0) for one frame — mass blink, then reappear+bounce.
Fix: `window._pulseRevealedAmounts` in both `walkStepUpdate` and
`renderBoard` (`board.js`) remembers what each reveal showed and holds it
through the gap; cleared when a freeze is installed (dice handler) and at
`_growUnfreeze`.

**Cause C — recreated chips lost their bounce guard.** A blinked chip came
back with `data-shown` reset, so the `prevShown >= amount` guard couldn't
stop a bounce replay. Fix: `_pileChipMemory` in `_reconcileBananaPiles`
re-seeds a chip recreated within 2.5s with its last shown amount. Also:
`_bounceFarmPile` now strips `.pile-bounce` + inline `animation-delay`
directly when its window ends (previously waited for the next render).

**Tests:** `test_pile_bounce.js` +H11 (blink recreation never re-bounces),
+H12 (blink + real growth still bounces once), +H13 (next-roll gap holds
revealed piles). `test_pile_persist.js` +P5 (sync-check the generation
guards); its `rollFreeze`/`unfreeze` emulators now mirror the
`_pulseRevealedAmounts` lifecycle. 59 assertions, all green.

**Live verification:** fresh instrumented game, 51 turns of auto-roll with
piles growing/stacking across turns: 0 blinks (every detach had
authoritative pile = 0), 0 duplicate bounces, 0 mass removals, no console
errors. Pre-fix the same setup blinked by turn ~25.
