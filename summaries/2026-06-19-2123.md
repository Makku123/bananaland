# Session 2026-06-19 2123 — Rich SB cross: card auction first, then deferred landing

Request: when a rich player **crosses** the Super Banana, the card auction should happen
**immediately**, then they continue, then **whatever the landing triggers** (Monkey Poker / a
farm auction) happens — instead of the prior behavior where a landing auction/poker pre-empted the
cross g-roll (the cross "yielded").

## Change (backend only) — deferred-landing reorder
The move flow resolved the LANDING before the cross, so a rich cross's interactive g-roll auction
yielded to a landing auction/poker. Reversed the order and deferred the landing:

- **Move sites (all 4: rollDice, useRollCard normal + cancel-HIT, debugMove):** now call
  `_resolveSuperBananaCross(cur, oldPos)` **before** `_processLanding`, and **skip** the immediate
  `_processLanding` when the cross returns true.
- **`_resolveSuperBananaCross`** now returns `true` and sets `this._crossLandingPending = player.id`
  only for the can-afford cross (which opens the cardpick card auction). Returns false for the +50
  case, hidden cross, no-cross, ghost/bankrupt (landing then runs immediately as before).
- **New `_resolvePendingCrossLanding()`** runs the deferred `_processLanding(crosser)` and clears the
  flag. Called from every card-auction conclusion: `_resolveAuction` tail, `pickCardAndPitch`
  free-award path, and the `_maybeDriveGhost` cardpick-clear branch. The auto-end after each is
  guarded by `!this.auction && !this.poker && !this.superBananaWin`, so if the deferred landing opens
  a farm auction or poker the turn isn't ended prematurely — that new interaction ends the turn when
  it resolves.
- New field `_crossLandingPending` (constructor + `_resetToLobby`).

**Why it's complete:** every card-auction resolution funnels through `_resolveAuction` —
including `_resolveSilentBid → _resolveAuction` (sealed/tie) and `_2v2Award → _resolveAuction`
(all team paths) and Buy Now — plus the free-award (`pickCardAndPitch`) and ghost-cardpick paths.
So the pending landing runs exactly once on every path. The can't-afford LANDING cardpick never sets
the flag (its landing already happened), so it won't spuriously run a deferred landing.

Result sequence for a rich cross: **card auction → (resolve) → crossed-into landing (farm auction /
Monkey Poker / grow)**. (Fog note: the walk still animates to the final tile before the card-auction
modal — the SB is fog-hidden so the frontend can't pause the walk at it without revealing it; the
EFFECT order is exactly as requested. Frontend needed no change — it just renders the card-auction
modal, then the farm-auction/poker modal.)
