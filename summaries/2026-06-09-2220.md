## Mount corruption — root cause found

The bananaland mount (virtiofs/FUSE from Windows) serves a **stale file
size** for any file already read through the mount before a host-side edit.
Content pages are fresh; the size is pinned for ≥3 minutes (probably longer)
and nothing in the sandbox refreshes it (`touch`, O_DIRECT,
`statx --cached=never` all stale). Verified with controlled probes:

- Pre-read file, host edit grows it 9→36 bytes → mount returns the new
  content truncated to 9 bytes.
- File never read through the mount before the edit → reads perfectly fresh.
- Matches every observed artifact: NUL tail padding = file shrank (pad is
  exactly old−new bytes); mid-line truncation = file grew; the earlier
  "duplicated chunks" copy = a mixed-cache window.

**Protocol going forward** (saved to memory): snapshot needed files to /tmp
at run start before any edits; after edits, reconstruct rather than re-read
(NUL-strip for shrinks, host-side tail splice for growth); always
fingerprint-check — `node --check` alone can pass on a truncated file.

**For Mark:** this is a Claude desktop app (virtiofs attr-cache) issue, not
a project issue — worth reporting to Anthropic.
